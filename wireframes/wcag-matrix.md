# WCAG 2.1 AA Mapping Matrix

**Project:** Community Healthcare Clinic: Accessible Healthcare Booking Portal
**Ticket:** MD-2026-0143
**Standard:** WCAG 2.1, Level AA
**Primary persona:** Priya Nair (NVDA + Firefox, keyboard only, braille display). See `persona.md`.

**How to use this document:** The matrix (sections 1 to 4) is written _before_ development as the accessibility plan. Section 5 is the verification log, completed _after_ the React build is tested. Section 6 is a quick sign-off checklist.

---

## 1. Perceivable

| Criteria ID & Name                   | Target Interface Component                                               | Technical Implementation Detail                                                                                                                                                                                                                                                   | Verification Strategy                                                                                                                                                                    |
| ------------------------------------ | ------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **1.3.1 Info and Relationships (A)** | All pages: landmarks, headings, form fields, service list, filter groups | Use `<header>`, `<nav>`, `<main>`, `<section>`, `<article>`, `<aside>`, `<footer>`. One `<h1>` per page with no skipped heading levels. Each input has `<label htmlFor>`. Related filter controls wrapped in `<fieldset>` with `<legend>`. Service results use `<ul>` and `<li>`. | Automated: axe-core rules `landmark-one-main`, `heading-order`, `label`. Manual: NVDA Elements List (`NVDA+F7`) to confirm headings, landmarks and form fields read in a sensible order. |
| **1.4.1 Use of Colour (A)**          | Slot availability, form errors, required fields                          | Never use colour alone for meaning. Availability uses text ("Available", "Fully booked") plus an icon. Errors use an icon, the text "Error:" and a red border. Required fields use the text "(required)" rather than a red asterisk only.                                         | Manual: view the pages in greyscale (browser dev tools, "Emulate vision deficiencies": achromatopsia) and confirm all states are still distinguishable.                                  |
| **1.4.3 Contrast (Minimum) (AA)**    | Body text, headings, links, buttons, placeholders, error text            | Body text `#3b4a57` on `#ffffff` = 9.0:1. Headings `#112231` on `#ffffff` = 16:1. Button text `#ffffff` on `#35647c` = 6.4:1. Error text `#b3261e` on `#ffffff` = 6.5:1. Large text meets at least 3:1. Computed values recorded in `main.css` comments.                          | Automated: Lighthouse and axe-core `color-contrast`. Manual: spot-check with the WebAIM Contrast Checker for every colour pair.                                                          |
| **1.4.4 Resize Text (AA)**           | Entire site                                                              | Font sizes in `rem`. No fixed-height text containers. Layout tested up to 200% browser zoom without loss of content.                                                                                                                                                              | Manual: set browser zoom to 200% and confirm nothing is clipped or overlaps.                                                                                                             |
| **1.4.10 Reflow (AA)**               | Landing page, listing page, booking form                                 | Responsive layout using flexbox and grid. No horizontal scrolling at 320 CSS px width (equivalent to 400% zoom on 1280px).                                                                                                                                                        | Manual: set viewport to 320px wide and zoom to 400%. Confirm single-column reading with no two-way scrolling.                                                                            |
| **1.4.11 Non-text Contrast (AA)**    | Input borders, focus rings, checkboxes, filter toggles, icons            | Input borders `#6b7f8c` on `#ffffff` = 4.2:1. Focus ring `#35647c` on `#ffffff` = 6.4:1. Icons carry a 3:1 contrast minimum against adjacent colours.                                                                                                                             | Manual: contrast checker on each component boundary. Automated: axe-core and Lighthouse cover part of this.                                                                              |
| **1.4.12 Text Spacing (AA)**         | Body copy, form labels, card content                                     | No fixed heights on text containers. Line height set to at least 1.5. No content is clipped when users apply the text spacing bookmarklet.                                                                                                                                        | Manual: apply the "Text Spacing" bookmarklet and check for clipped or overlapping text.                                                                                                  |

## 2. Operable

| Criteria ID & Name                      | Target Interface Component                                                                                    | Technical Implementation Detail                                                                                                                                                                                                       | Verification Strategy                                                                                                                                            |
| --------------------------------------- | ------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **2.1.1 Keyboard (A)**                  | Every control: links, buttons, search, filter accordion, toggle filters, date and time selection, form, modal | Use native elements (`<button>`, `<a>`, `<input>`, `<select>`) wherever possible. No click handlers on `<div>`. Custom controls (accordion header, toggle filters) are real `<button>` elements and operate with `Enter` and `Space`. | Manual: complete the full booking journey with the keyboard only (`Tab`, `Shift+Tab`, `Enter`, `Space`, `Esc`, arrow keys). Mouse unplugged.                     |
| **2.1.2 No Keyboard Trap (A)**          | Confirmation modal, filter accordion                                                                          | Modal contains focus while open but closes on `Esc` and via a visible Close button. Focus returns to the trigger on close. No other component captures focus.                                                                         | Manual: tab through the whole page including the modal and confirm you can always leave. Component test: simulate `Esc` and assert focus returns to the trigger. |
| **2.2.1 Timing Adjustable (A)**         | Booking form, session handling                                                                                | No automatic timeouts on the prototype. Form state is held in React state so it is not lost on a failed submit.                                                                                                                       | Manual: leave the form idle for 10 minutes and confirm data is intact.                                                                                           |
| **2.4.1 Bypass Blocks (A)**             | Every page                                                                                                    | Skip link (`<a class="skip-link" href="#main">`) is the first focusable element. `<main id="main" tabindex="-1">` receives focus when activated.                                                                                      | Manual: press `Tab` once on page load and confirm the skip link appears and works. Automated: axe-core `bypass`.                                                 |
| **2.4.2 Page Titled (A)**               | Every route                                                                                                   | Unique, descriptive `<title>` per route (for example "Book an appointment – Community Clinic"). Updated on React route changes.                                                                                                       | Manual: confirm the title announces on navigation in NVDA. Automated: Lighthouse `document-title`.                                                               |
| **2.4.3 Focus Order (A)**               | Every page, modals, view switches                                                                             | DOM order matches visual order. No positive `tabindex` values. On route change, focus moves programmatically to the page `<h1>` via `useRef`. On modal open, focus moves to the modal heading.                                        | Manual: record the Tab sequence for each page and compare with the visual order. Component test: assert `document.activeElement` after each transition.          |
| **2.4.4 Link Purpose (In Context) (A)** | Service cards, navigation, "Book" links                                                                       | Link text is descriptive ("Book diabetic eye screening"). Where a visible label must stay short, use `aria-label` that begins with the visible text.                                                                                  | Manual: use NVDA Links List (`NVDA+F7`, Links tab) and confirm every link makes sense out of context.                                                            |
| **2.4.6 Headings and Labels (AA)**      | Page sections, form fields                                                                                    | Headings describe the topic of each section. Labels are specific (for example "Date of birth", not "Date").                                                                                                                           | Manual: read the headings list and form fields list aloud with NVDA.                                                                                             |
| **2.4.7 Focus Visible (AA)**            | All focusable elements                                                                                        | Global `:focus-visible { outline: 3px solid #35647c; outline-offset: 3px; }`. Light-coloured ring on dark surfaces. Default outlines are never removed without replacement.                                                           | Manual: tab through every page and confirm a clear ring on every control. Visual regression screenshot.                                                          |

## 3. Understandable

| Criteria ID & Name                                       | Target Interface Component                 | Technical Implementation Detail                                                                                                                                                                               | Verification Strategy                                                                                                                         |
| -------------------------------------------------------- | ------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| **3.1.1 Language of Page (A)**                           | Document root                              | `<html lang="en">` set in `index.html`.                                                                                                                                                                       | Automated: axe-core `html-has-lang`.                                                                                                          |
| **3.2.1 On Focus (A)**                                   | All form fields and filters                | Receiving focus never triggers a change of context (no auto-submit, no navigation, no pop-ups on focus).                                                                                                      | Manual: tab through the form and confirm nothing changes unexpectedly.                                                                        |
| **3.2.2 On Input (A)**                                   | Category filters, dropdown selects, search | Changing a filter updates the list in place and announces the result count. It does not navigate away or move focus. Submission requires an explicit button.                                                  | Manual: change each filter with the keyboard and confirm focus stays put.                                                                     |
| **3.3.1 Error Identification (A)**                       | Booking form                               | Invalid fields get `aria-invalid="true"` and an inline error message linked through `aria-describedby`. On submit with errors, an error summary receives focus and lists each problem as a link to its field. | Manual: submit an empty form with NVDA and confirm errors are announced. Component test: assert `aria-invalid` and `aria-describedby` values. |
| **3.3.2 Labels or Instructions (A)**                     | Booking form                               | Visible `<label htmlFor>` on every input. Format hints (for example "DD/MM/YYYY") in helper text, associated via `aria-describedby`.                                                                          | Manual: confirm NVDA reads label, role, then helper text on each field. Automated: axe-core `label`.                                          |
| **3.3.3 Error Suggestion (AA)**                          | Date of birth, phone, email fields         | Error messages say how to fix the problem ("Enter your date of birth as DD/MM/YYYY, for example 04/03/1978").                                                                                                 | Manual: enter bad values in every field and review the message wording.                                                                       |
| **3.3.4 Error Prevention (Legal, Financial, Data) (AA)** | Appointment booking and cancellation       | A review step shows all details before final confirmation. Cancellation requires an explicit confirm. Booking can be edited before submit.                                                                    | Manual: complete the flow and confirm a review step appears with an option to go back.                                                        |

## 4. Robust

| Criteria ID & Name              | Target Interface Component                                                    | Technical Implementation Detail                                                                                                                                                                                                                                     | Verification Strategy                                                                                                                                                       |
| ------------------------------- | ----------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **4.1.2 Name, Role, Value (A)** | Filter accordion, toggle filters, tabs, modal, form fields                    | Accordion header: `<button aria-expanded={open} aria-controls="panel-id">`. Toggle filter: `<button aria-pressed={on}>`. Modal: `role="dialog"`, `aria-modal="true"`, `aria-labelledby`. Values are driven directly from React state so they cannot go out of sync. | Manual: toggle each control with NVDA and confirm "expanded/collapsed" and "pressed/not pressed" are announced. Component test: assert attributes update after interaction. |
| **4.1.3 Status Messages (AA)**  | Search results count, validation summary, booking confirmation, loading state | A persistent `aria-live="polite"` region (present in the DOM on load) announces result counts ("5 services found") and confirmations. Errors on submit use `aria-live="assertive"` or `role="alert"`. `aria-busy="true"` on the results list while loading.         | Manual: run NVDA with speech viewer open and log every announcement. Component test: assert live region text after search and submit.                                       |

## 6. Tools Used

- **axe-core** (via the axe DevTools extension or `jest-axe` in component tests)
- **Lighthouse** (Chrome DevTools, Accessibility category)
- **NVDA + Firefox** (primary screen reader test)
- **VoiceOver + Safari** (secondary screen reader test)
- **WebAIM Contrast Checker**
- **Keyboard only**, with the mouse unplugged

> Automated tools catch roughly a third of WCAG issues. The manual screen reader and keyboard checks are what prove the criteria are actually met.
