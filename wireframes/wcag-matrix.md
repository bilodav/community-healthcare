# WCAG 2.1 AA Mapping Matrix

**Project:** Community Healthcare Clinic: Accessible Healthcare Booking Portal
**Ticket:** MD-2026-0143
**Standard:** WCAG 2.1, Level AA
**Primary persona:** Priya Nair (NVDA + Firefox, keyboard only, braille display). See `persona.md`.

**How to use this document:** The matrix (sections 1 to 4) is written _before_ development as the accessibility plan. Section 5 is the verification log, completed _after_ the React build is tested. Section 6 lists the tools used.

### 5a. Automated results

**Wireframes (static HTML), run 2026-10-11**

Tool: axe-core 4.14.0 in jsdom, run with `node scripts/a11y-wireframes.mjs`. Rule tags: `wcag2a`, `wcag2aa`, `wcag21a`, `wcag21aa`, `best-practice`. The `color-contrast` rule is switched off because jsdom does no layout or painting; contrast is covered by the computed audit in `main.css` and must be re-checked in a real browser (see 5b).

**Computed contrast:** every text pairing in the CSS audit block passes 4.5:1 (lowest: `#526069` on `#f5d4c6` at 4.67:1) and every non-text pairing passes 3:1 (lowest: header glass focus ring at 3.40:1). See the "CONTRAST AUDIT" and "FOCUS INDICATOR AUDIT" comments in `main.css` and `src/App.css`.

## 6. Tools Used

- **axe-core 4.14.0** (via `scripts/a11y-wireframes.mjs`, the axe DevTools extension, and `vitest-axe` in component tests)
- **html-validate** (HTML structure check on the wireframes)
- **Lighthouse** (Chrome DevTools, Accessibility category)
- **NVDA + Firefox** (primary screen reader test)
- **VoiceOver + Safari** (secondary screen reader test)
- **WebAIM Contrast Checker**
- **Keyboard only**, with the mouse unplugged

> Automated tools catch roughly a third of WCAG issues. The manual screen reader and keyboard checks are what prove the criteria are actually met.
